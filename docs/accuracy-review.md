# 准确性复盘与项目对照

版本：0.3.0。项目状态：实验性 Linux X11 / Windows 10、11 桌面辅助工具，尚无受控实机命中率数据。

## 0.3.0：456 分画面的细长圆台

用户运行记录保存了 87 次按压，最后画面分数显示 456，棋子仍在当前平台上。
停止原因是下一块绿色圆台带有细长底座，整体连通区域高宽比超过旧筛选上限 1.4，被提前剔除。
放宽整体物体筛选到 2.2 后，仍单独验证顶面，得到圆台中心约 `(299.0,618.1)`。
新增三种尺寸、两个方向的回归测试，修复前六种情况均失败，修复后通过。
回放该次 87 张跳前原图，无新增拒绝或超过 5px 的目标变化；这是离线定位比较，不是新增 87 跳实机验收。

同版本加入 Windows 后端。Windows 的按压参数必须独立校准，不能把 Linux 的运行记录当成 Windows 稳定性证据。

## 0.2.2：纹理、装饰与阴影导致的系统性问题

新记录暴露出纯色顶面假设的局限，不能靠继续调一个颜色阈值解决：

- 棕色大理石平台没有大块同色顶面，因而被拒绝识别。本轮增加受约束的菱形上边缘拟合，检查两边斜率、拟合残差、转角、对称关系及内部前景覆盖；可见角与轻微遮挡角必须给出相近尺寸。原图定位约 `(440.1,610.3)`。
- 红色屋顶被黄色装饰条分成两块，旧算法把其中一块当成完整平台，返回 `(434.3,568.9)`。现在排除中心明显偏离上顶点的局部色块，并通过完整顶面找到白点 `(473.8,589.0)`。
- 同一帧的棋子头部与蓝灰色阴影连通，头径由正常约 38.8px 被扩大成 59.5px。改为在球体上部选取与棋子轴线一致的连通部分测量，回归图恢复为 38.8px。与目标定位一起修复后，该帧模型估计从 324.4ms 变为 536.9ms；这仍是模型预测，不是新的实机校准结果。
- 回放中发现旧的唱片机画面也曾选中偏右色块。其左上边缘被棋子遮挡，无法验证完整顶面，现在拒绝该帧。边缘法并不保证所有纹理平台都能继续跳。

在 19 张历史跳前原图上离线回放，18 张返回检测结果，1 张上述遮挡唱片机画面拒绝。
这只是检测执行统计，不能解释为 18/19 的命中率。新添两种纹理画面各 3 个尺寸、2 个方向的坐标回归，
以及头径和遮挡拒绝回归。最新 9 跳记录中客户端时长与计划的最大偏差约 1.59ms，
未发现输入计时偏差足以解释本轮识别错误的证据；游戏引擎接收时刻仍未知。

## 0.2.1：第 8 跳后停止的复现与修复

本地记录 `20261023T070203561924Z` 的第 8 跳前后原图显示，棋子落到绿色方块上，分数从 16 变为 17。
停止发生在识别下一块灰色条纹平台时。并非这一次跳跃已经失败。

- 绿色平台顶面与右侧面 RGB 差值总和约为 26，旧容差 36 将它们合并，目标纵坐标被拉到约 631。
  收紧顶面颜色容差到 18 后，分离出顶面，并找到白点 `(486.1,582.5)`。
- 灰色条纹平台的阴影延伸到窗口左边，与细黑边相连，使整个候选连通域触及扫描上界而被过滤。
  先排除窄窗口边缘，再对分离出来的顶面检查边界；阴影触边不再直接否决整个物体。
  修复后的目标为 `(207.8,565.0)`；顶面本身被截断仍停止。
- 8 次客户端按压偏差均在约 2.1ms 内，本轮证据指向定位问题，未据此修改系数或生成校准文件。

新增真实原图回归，灰色平台覆盖 360/699/1080px 宽度及左右翻转，并测试顶面被裁掉时拒绝识别。
`examples/green-marker-corrected.png`、`examples/striped-platform-corrected.png` 是离线修复预览；
修复后的实际连续跳跃效果尚待运行验证。

## 已确认的错误

用户一次运行保存的第 5 跳计划中，棋子约为 `(526.6,753.9)`，目标约为
`(0.65,406.2)`，估计按压 `1256.2ms`。同一张带标注画面显示，真正的下一跳台是左上的绿色方块，
中心白点约 `(197,556)`。图中的游戏分数为 14，但这不能当作脚本命中率。

旧版每行取左右边缘颜色的中位数。如果其中一边被旧平台覆盖，会得到一个实际上不存在的背景颜色。
真正背景于是成为巨大的前景连通域，且旧版没有拒绝靠窗口边界的目标，也没有强制要求可靠的顶面。
这次错误首先属于**定位错误**，不能靠增加或减少按压系数解决。

另一个可复现的问题在计时：旧版在 `down()` 返回后才计算截止时刻，
而 `down()` 在发送按下事件后还会等待 X server 同步。这段等待被额外加到了按住时间里。
模拟 40ms 同步延迟的回归测试验证了修复后的截止时刻会计入这段等待。

## 0.2.0 的改动

1. 根据上方较空区域估计背景参考色，再选每行接近参考色的像素，避免混合左右边缘颜色。
2. 拒绝边缘截断的候选、扫描边界上的大块伪前景，以及投影关系不合理的目标。
3. 没有可靠顶面或中心点时停止，取消仅凭外轮廓猜测落点的行为。
4. 从输入事件提交时刻起计算按压截止时间，记录 `client_hold_ms`；延迟偏大时释放并停止。
5. 每跳保存原始起跳图、计划、落地等待后的原图和时长数据；识别失败也保留拒绝画面。
6. 新增宽度归一化水平位移校准。至少 3 条已确认样本，覆盖至少 3 个距离及 15% 画面宽度的跨度；
   拟合误差过大或预测严重超出样本范围时拒绝使用。

## 0.3.1 小圆台漏检

用户运行到 666 分后，画面中的白色小圆台仍未被识别。原始游戏图缩放到 540px 宽后，
白色顶面连通域只有 46px 宽；浅色边缘接近背景，使它与底座分离。
旧版要求候选至少占画面宽度的 10%，因此顶面被过滤，最终只分析了下面的灰色底座和阴影。
这是定位漏检，调整按压系数不会解决。

现在小候选先提取顶面颜色，要求形状与完整实心椭圆的交并比至少为 90%，并检查尺寸、扁率和面积。
通过检查的小顶面可以独立于底座被选中；原有边界、投影方向、稳定帧和输入保护继续生效。
新增真实原图多分辨率/方向测试、不同直径与颜色的合成圆台，以及矩形、残缺与空心图案拒绝测试。
原图离线目标约 `(512,570)`，最近两次运行的 193 张跳前图没有新增拒绝或超过 5px 的目标变化。
这些证据说明当前回归场景可识别，不能证明所有特殊平台或真实跳跃都已稳定。

## 仍然不足的地方

- **没有当前设备的真实校准样本。** 新增模型可用，不等于已经校准。
- **没有可靠的成功判定。** 画面变化、发出输入或分数出现在截图上，都不能单独证明这次跳跃成功。
- **相机会移动。** 跳前、跳后直接相减屏幕坐标不是实际位移；采样必须在相机移动前测量，或可靠补偿相机平移。
  当前没有实现这个补偿，故不自动在线学习。
- **特殊平台与纹理仍可能被拒绝。** 更严格的检测会减少误按，但也可能更早停止。
- **客户端计时不是游戏引擎收到事件的精确时刻。** X server、窗口系统和系统负载仍会影响输入。
- **回归测试不是命中率试验。** 尚无多个随机场景、重复运行和独立人工标注下的准确率统计。

后续验收应先采集短、中、长三个距离的实际数据，再在新场景上验证。
不能把拟合样本误差、测试数量或个别得分写成游戏命中率。
