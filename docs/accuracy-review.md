# 准确性复盘与项目对照

版本：0.2.0。项目状态：实验性 Linux/X11 桌面辅助工具，尚无受控实机命中率数据。

## 已确认的错误

用户一次运行保存的第 5 跳计划中，棋子约为 `(526.6,753.9)`，目标约为
`(0.65,406.2)`，估计按压 `1256.2ms`。同一张带标注画面显示，真正的下一跳台是左上的绿色方块，
中心白点约 `(197,556)`。图中的游戏分数为 14，但这不能当作脚本命中率。

旧版每行取左右边缘颜色的中位数。如果其中一边被旧平台覆盖，会得到一个实际上不存在的背景颜色。
真正背景于是成为巨大的前景连通域，且旧版没有拒绝靠窗口边界的目标，也没有强制要求可靠的顶面。
这次错误首先属于**定位错误**，不能靠增加或减少按压系数解决。

另一个可复现的问题在计时：旧版在 `down()` 返回后才计算截止时刻，
而 `down()` 在发送按下事件后还会等待 X server 同步。这段等待被额外加到了按住时间里。
模拟 40ms 同步延迟的回归测试验证了修复后的截止时刻会计入这段等待。

## 与其他实现的对照

| 来源 | 核对到的做法 | 本项目的不足与处理 |
|---|---|---|
| [wangshub 原版](https://github.com/wangshub/wechat_jump_game/blob/master/wechat_jump_auto.py) | 根据棋子头部直径归一化距离，用非线性公式换算时长 | 原版公式不是当前 Linux 微信的实测参数。保留为明确标注的未校准后备模型，不声称默认精准 |
| [wangshub slim](https://github.com/wangshub/wechat_jump_game/blob/master/wechat_jump_auto_slim.py) | 使用水平位移/屏幕宽度，减少对纵坐标和棋子尺寸的依赖 | 新增基于实测水平位移占比的校准模型；没有把其 1700ms 常量冒充本机实测值 |
| [wangshub AI 版](https://github.com/wangshub/wechat_jump_game/blob/master/wechat_jump_auto_ai.py) 与 [common/ai.py](https://github.com/wangshub/wechat_jump_game/blob/master/common/ai.py) | 收集样本，拟合距离和按压时长，并采集落地阶段截图 | 新增离线最小二乘拟合、每跳前后原图与客户端按压时长记录。未实现自动验证落地成功，也不自动用错误目标训练 |
| [shenfe 识别](https://github.com/shenfe/wechat-jump-game/blob/master/src/detect.py) | 模板匹配、双帧检查、边界与特殊形状处理 | 单纯颜色连通域不够稳健。增加顶面、边界和投影几何检查，无法可靠识别时停止。没有新增不可用的 OpenCV 依赖 |
| [shenfe 时长函数](https://github.com/shenfe/wechat-jump-game/blob/master/src/distance_time.py) | 使用其设备上统计得到的线性关系 | 不照搬其设备系数；校准文件必须由用户确认的实际位移/时长样本生成 |

上述代码仅用于思路对照，未引入其 ADB、反检测代码、TensorFlow、pandas 或 sklearn。

## 0.2.0 的改动

1. 根据上方较空区域估计背景参考色，再选每行接近参考色的像素，避免混合左右边缘颜色。
2. 拒绝边缘截断的候选、扫描边界上的大块伪前景，以及投影关系不合理的目标。
3. 没有可靠顶面或中心点时停止，取消仅凭外轮廓猜测落点的行为。
4. 从输入事件提交时刻起计算按压截止时间，记录 `client_hold_ms`；延迟偏大时释放并停止。
5. 每跳保存原始起跳图、计划、落地等待后的原图和时长数据；识别失败也保留拒绝画面。
6. 新增宽度归一化水平位移校准。至少 3 条已确认样本，覆盖至少 3 个距离及 15% 画面宽度的跨度；
   拟合误差过大或预测严重超出样本范围时拒绝使用。

## 仍然不足的地方

- **没有当前设备的真实校准样本。** 新增模型可用，不等于已经校准。
- **没有可靠的成功判定。** 画面变化、发出输入或分数出现在截图上，都不能单独证明这次跳跃成功。
- **相机会移动。** 跳前、跳后直接相减屏幕坐标不是实际位移；采样必须在相机移动前测量，或可靠补偿相机平移。
  当前没有实现这个补偿，故不自动在线学习。
- **特殊平台与纹理仍可能被拒绝。** 更严格的检测会减少误按，但也可能更早停止。
- **客户端计时不是游戏引擎收到事件的精确时刻。** X server、窗口系统和系统负载仍会影响输入。
- **回归测试不是命中率试验。** 尚无多个随机场景、重复运行和独立人工标注下的准确率统计。

后续验收应先采集短、中、长三个距离的实际数据，再在新场景上验证。
不能把拟合样本误差、测试数量或个别得分写成游戏命中率。
